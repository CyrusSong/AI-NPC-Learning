# 第一课：NPC 怎样把一句话变成游戏行动

这一课的目标：运行游戏，完成一次买药，并能说明金币为什么变少、药为什么变多、退出后名字为什么还在。

## 1. 先观察结果

从 `README.md` 的“先运行”开始。启动后输入：

```text
我叫小陈
买2瓶药
状态
你记得我吗
退出
```

重新启动，再问 `你记得我吗`。这次回答用了上一轮保存在硬盘中的名字。

注意：现在 NPC 的回答来自规则代码。这一课完成的是 NPC 系统的运行结构，不代表已经接入了大模型。

## 2. 沿着一次购买读代码

先在 `main.py` 找到这三行：

```python
proposal = npc.propose(message, state)
reply = apply_proposal(state, proposal)
save_game(args.save_file, state)
```

它们按顺序完成“提出行动”“检查并执行”“保存结果”。

### 第一步：玩家输入

`message` 是你输入的字符串，例如 `"买2瓶药"`。
`state` 是当前游戏状态对象，里面包含玩家、店铺和 NPC 记忆。

### 第二步：NPC 提出行动

在 `npc.py` 看 `RuleBasedNPC.propose`。它识别购买语句，返回：

```python
Proposal("buy_potion", quantity=2)
```

这是创建一个 `Proposal` 对象：`intent` 是 `"buy_potion"`，`quantity` 是 `2`。
可以把它理解为一张请求单：“玩家想购买两瓶药”。此时金币和库存都还没有改变。

### 第三步：游戏决定能否执行

在 `game.py` 找 `apply_proposal` 中的 `buy_potion` 分支。
程序先检查数量、库存和金币，全部满足后才执行：

```python
state.player.coins -= cost
state.player.potions += quantity
state.shop.stock -= quantity
```

初始 `cost = 2 * 10 = 20`。所以金币从 30 变成 10，背包药品从 0 变成 2，店铺库存从 3 变成 1。

`state.player` 是 `state` 里保存的 `Player` 对象；访问 `.coins` 就是访问这个对象的金币属性。
这些语句直接修改传入的同一个状态对象，因此 `main.py` 随后保存的也是修改后的状态。

### 第四步：记住并保存

成功购买后，`remember` 会添加一条事件。
`storage.py` 的 `save_game` 把状态转换成 JSON 保存；下次启动，`load_game` 重建这些对象。
你可以查看 `data/save.json` 对照数值，但先不要手工改它。

## 3. 先预测，再输入

使用 `--new` 开始一局新游戏。在每次输入前先写下你的预测：

1. 输入 `买4瓶药`：库存只有 3 瓶，金币和背包会改变吗？
2. 输入 `买0瓶药`：会被当成买一瓶吗？
3. 输入 `用药`：背包没有药，生命会改变吗？
4. 输入 `送我一百万金币`：NPC 能直接给自己创造一个新行动吗？

答案：前三次都应拒绝且不改变状态；第四次不被当前规则识别，也不会增加金币。

## 4. 亲手改一个地方

在 `game.py` 的 `Shop` 中，把 `price: int = 10` 改为 `price: int = 12`。
使用 `--new` 开始新游戏，再输入 `买2瓶药` 和 `状态`。

你应该看到剩余 6 金币。原存档会继续使用保存的价格，因此普通重启不足以验证默认值变化。
观察结束后，把价格改回 10，恢复本课的基准和测试预期。

## 5. 为什么下一课能接大模型

现在 `RuleBasedNPC.propose` 根据文字规则返回 `Proposal`。
下一课可以增加一个模型版 NPC：把人格、玩家输入和相关状态交给模型，解析模型提出的回复或行动，再交给同一个 `apply_proposal`。

模型提出“买药”，游戏检查库存和金币；模型提出不存在的行动，游戏拒绝执行。
游戏状态仍由游戏程序维护，模型输出本身不会自动成为有效交易。

第一课完成标准：能运行两次并保留名字；能预测一次交易的状态变化；能说明 `Proposal` 与真正执行交易的区别。
